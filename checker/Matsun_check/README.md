# Matsun テストデータ案（データ取り込み・前処理）

データ取り込み・前処理工程（`yaiba_loader.py`、`core.load`）で欲しいテストデータの案をまとめたフォルダ。
「チェックしたい観点」と「どういったデータが欲しいのか」を、次の2つの文書で説明する。

## 文書の構成

| 文書 | 内容 | 答えている問い |
| --- | --- | --- |
| [異常系の棚卸.md](異常系の棚卸.md) | 実ログを正常系とみなし、取り込み処理で想定される異常系を20項目洗い出したもの。項目ごとに、起こりやすさ・今の挙動・中間テーブルや可視化への影響をまとめている | チェックしたい観点は何か |
| [テストデータ案.md](テストデータ案.md) | 棚卸しした20項目を、3つのテストデータで効率よく検知するための案。データごとに、どういったデータが欲しいか・なぜ欲しいか・どの異常系を検知するかを書いている | どういったデータが欲しいのか |

読む順番は「異常系の棚卸.md → テストデータ案.md」。
テストデータ案.md は、棚卸しの No. と分類（致命的・完全性・値の誤り・可視化・機密性・可用性）を使って説明している。

## 基本の考え方

- **期待値は「本来どう動くべきか」から決める。** 現在の実装の挙動を期待値にすると、実装の問題がテストで隠れてしまう。あるべき動きを期待値にすれば、違いがテストの失敗として表に出る
- **「処理が止まらない」だけでなく、中間テーブルが正しいかを確かめる。** 棚卸しでは、エラーは出ないのに中間テーブルが黙って壊れる異常系（完全性）が最も多かった
- **正解を決めた合成データを使う。** 実ログは個人情報を含むためテストには使わない。実ログで起きていた出来事を架空名で再現し、行数や件数で判定できるようにする

## 3つのテストデータ案の概要

| 案 | どういったデータか | 主に検知する異常系 |
| --- | --- | --- |
| 案1 | 実ログの「癖」（ワールドの移動、入り直し、ID の変化、同じ秒の重複、日付またぎ、途中で切れた最終行など）をすべて再現した小さな合成ログ | 完全性・値の誤り・可視化 |
| 案2 | 案1の正常部分をもとに、1か所だけ壊した小さなファイルのセット | 致命的・機密性（エラーメッセージ） |
| 案3 | 案1を拡大した 100MB 超のログ | 可用性・機密性（出力ファイル） |

3つで、棚卸しした20項目すべてを検知できる。

## 実ログの扱い

- 棚卸しの根拠にした実ログは `data/` に置く（`data/output_log_2025-12-11_21-12-28.txt`、約3時間・42人・14MB）
- 実ログには表示名などの個人情報が含まれるため、`data/` の中身はコミットしない（`data/.gitignore` で除外している）
- 各自が手元に置いて使う
