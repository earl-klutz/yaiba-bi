# 異常系の棚卸（データ取り込み・前処理）

実ログ（`data/output_log_2025-12-11_21-12-28.txt`、約3時間・42人・14MB）を正常系とみなし、
`yaiba_loader.py`（`core.load`）で想定される異常系を洗い出した。
ここからテストデータを作る。

## 分類

| 分類 | 意味 |
| --- | --- |
| 致命的 | 中間テーブルが作られない、または使えない |
| 完全性 | 処理は通るが、中間テーブルが黙って壊れる |
| 値の誤り | 列・行の構成は保たれるが、値が間違っている |
| 可視化 | 中間テーブルは正しいが、可視化の結果を誤解させる |
| 機密性 | 個人情報（ユーザー名）が漏れる |
| 可用性 | 処理が止まる、または使えないほど遅くなる |

## 確認方法

- 「今の挙動」は、合成ログまたは実ログを `core.load()` に通して確認した（2026-11-08、Windows / Python 3.12、`.venv`）
- No.1〜4、6、7、14、17、18 は実ログの集計と読み込み結果から確認した
- No.19 は、実ログの表示名と `usr_` の ID が各出力ファイルに含まれていないかを件数で調べた。エラーメッセージは、壊れた行を含む合成ログ5種類で確かめた
- No.20 は 111MB の合成ログで計測した。Colab で何MB から止まるかは試しておらず、メモリ使用量の比率からの推定である
