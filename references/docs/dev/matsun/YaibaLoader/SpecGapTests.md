# 設計書と実装の乖離を検出するテスト仕様

## 目的

`設計書_データ取り込み・前処理（I-O標準化）.md` に定められた仕様を期待値とし、
`yaiba_loader.py` の実装が満たしているかを検証する。

現状の挙動を期待値にすると乖離をテストで固定してしまうため、
**期待値の出典を実装ではなく設計書に置く**。乖離は必ずテストの失敗として現れる。

```
通常のテスト : 実装の挙動 → 期待値 → テスト   (乖離が隠れる)
本仕様       : 設計書     → 期待値 → テスト   (乖離が失敗として出る)
```

## テスト設計書への追加提案

後述のテスト仕様27項目のうち16項目は、テスト設計書に該当する方針がない。
それらを実施するには以下の観点を `### 方針` に追加する必要がある。
いずれもローダー固有ではなく、他機能にも当てはまる。

残る11項目は既存の方針でカバーされるため、追加は不要である。

### 1. 入力

```
- 入力データのバージョンに応じた挙動が仕様通りであること
```

### 2. 処理

```
- 引数の値が処理に反映されること
```

### 3. 出力

```
- 出力値が仕様の値域に収まっていること
- 出力値がNoneとなる条件が仕様通りであること
- 時刻を表す出力値の基準が仕様通りであること
- 設計書に定義された構成要素がすべて実装されていること
```

## テスト仕様

計27項目。すべて現状の実装では失敗する。

行末の `*` は、既存のテスト設計書に該当する方針がなく、
上記「テスト設計書への追加提案」の6行を必要とする項目を示す (16項目)。
印のない項目 (11項目) は既存の方針でカバーされる。

`(要確認)` は、設計書の記述が実装より古く、仕様の再確認が必要な項目を示す。

### 1. 入力

```
- ログファイルパスが str 型でない場合に拒否されること
- 秒粒度が int 型でない場合に拒否されること
- 秒粒度が 1 未満の場合に拒否されること
- 秒粒度が 3600 を超える場合に拒否されること
- 匿名化フラグが bool 型でない場合に拒否されること
```

### 2. 処理

```
- 秒粒度が 1 のとき velocity_x/y/z にVRChatログの値がそのまま入ること * (要確認)
- 秒粒度が 1 を超えるとき velocity_x/y/z に前回レコードとの差が入ること * (要確認)
- 匿名化フラグが False のとき user_name に元の表示名が入ること *
- 時刻基準点を与えたとき全レコードの時刻が補正されること *
- 時刻基準点が None のとき補正されないこと *
- 時刻基準点による補正が position と attendance の両方に適用されること *
- VRChatログバージョン 1.0.0 未満のとき location_y に None が入ること *
```

### 3. 出力

```
- attendance の列が設計書の定義と一致すること
- position の second の TimeZone が UTC であること *
- attendance の second の TimeZone が UTC であること *
- event_day の TimeZone が JST であること *
- event_day の型が datetime であること
- location_y の型が Optional[float] であること *
- rotation_1 の値が 0 以上 360 未満であること *
- rotation_2 の値が 0 以上 360 未満であること *
- rotation_3 の値が 0 以上 360 未満であること *
```

### 4. エラー処理

```
- 引数が不正な場合に ValueError が送出されること
- レコードに不備がある場合に is_error を True にして処理が継続すること
```

### 5. 外部I/O

```
- YAIBA出力ログ(.csv)を読み込めること
- YAIBA出力ログ(.json)を読み込めること
- CSVファイルを読み込んだ場合に attendance が None であること *
- LogData が save メソッドを持つこと *
```

## 設計書側の更新が必要な項目

以下は実装が正しく、設計書の記述が古いため、設計書の更新が必要となる。
テスト仕様には含めない。

| 箇所 | 設計書の記述 | 実装 | 経緯 |
|---|---|---|---|
| 入力仕様 (L47, L57) | `location_dx, location_dy, location_dz` | `velocity_x, velocity_y, velocity_z` | 設計書発効後に設計者と協議し velocity に統一 |
| 出力仕様 position (L113-115) | `location_dx, location_dy, location_dz` | `velocity_x, velocity_y, velocity_z` | 同上 |
| 性能・品質要件 (L223-225) | `location_dx, location_dy, location_dz` | `velocity_x, velocity_y, velocity_z` | 同上 |

生の YAIBA 出力のキーも `velocity_x/y/z` であることを実データで確認済み。

### 要確認

velocity への統一に伴い、以下の仕様が現在も有効かを設計者に確認する必要がある。

- 「秒粒度が 1 の場合はVRChatログデータをそのまま使う」(L224)
- 「秒粒度が 1 を超える場合は前回レコードとの差を使う」(L225)

これらは変位 (displacement) を前提に書かれた記述である。
速度 (velocity) に変わった場合、前回レコードとの差を取る処理が同じ意味を持つかは自明でない。

## 実施上の注意

### 既知の乖離は xfail でマークする

全項目が失敗したままではCIが機能しないため、`@pytest.mark.xfail` を用いる。
`reason` に設計書の行番号を記載することで、テストコードから根拠を辿れる。

```python
@pytest.mark.xfail(reason="設計書L222: rotation は 0<=x<360 だが実データに -0.0057 が存在")
def test_rotation_range(logdata):
    for col in ["rotation_1", "rotation_2", "rotation_3"]:
        v = logdata.get_position()[col]
        assert ((v >= 0) & (v < 360)).all(), f"{col} が範囲外"
```

実装が修正されると `XPASS` となり、マークを外す合図になる。

### 匿名化フラグの判定方法

匿名化後の値はパースのたびに変わるため、`True` と `False` の出力を比較するだけでは
**機能が未実装でも差分が出て合格してしまう**。
生レコードの表示名と一致することまで確認する必要がある。

### テストデータ

以下が必要だが、現時点で手元にあるのは VRChatログ (.txt) 1件のみ。

- VRChatログバージョン 1.0.0 未満と以上のログ (バージョン差の検証用)
- YAIBA出力ログ (.csv) (CSV読み込みと attendance=None の検証用)
- YAIBA出力ログ (.json) (JSON読み込みの検証用)
